# Ассемблер и интерпретатор учебной виртуальной машины (вариант №12)

Практическая работа №3 по дисциплине «Конфигурационное управление».

## Общее описание

Ассемблер и интерпретатор для учебной виртуальной машины (УВМ). Команды УВМ занимают 6 байт, поддерживаются четыре
команды: загрузка константы, чтение из памяти, запись в память и унарная операция `sqrt()`.

Текущее состояние — **этап 3 (интерпретатор и операции с памятью)**.

Ассемблер (`main.py`) читает программу на языке ассемблера в формате YAML, проверяет её, переводит во внутреннее
представление (для каждой команды хранятся поля `A`, `B` и `C` со значениями), затем в машинный код и записывает его
в двоичный файл. На экран выводится размер файла в байтах. В режиме тестирования (`--test`) дополнительно выводится
машинный код в байтовом формате, как в тестах из спецификации УВМ.

Интерпретатор (`interpreter.py`) читает двоичный файл, переводит каждую команду обратно во внутреннее представление
и выполняет её. Реализованы команды загрузки константы, чтения и записи памяти. После выполнения программы
выбранный диапазон памяти данных сохраняется в XML-файл (дамп памяти).

Команда `sqrt()` в интерпретаторе (этап 4) и тестовая задача (этап 5) будут добавлены на следующих этапах.
Пока интерпретатор, встретив `sqrt`, завершается с ошибкой.

Язык реализации — Python 3.8+. Для чтения YAML используется библиотека PyYAML.

## Описание функций и настроек

### Язык ассемблера

Программа — YAML-файл со списком команд. Каждая команда — запись «имя команды: операнды», операнды задаются
словарём `ключ: значение`. Все значения — неотрицательные целые числа, которые должны помещаться в поле команды.
Комментарии YAML (`# ...`) допускаются.

| Команда      | Операнды                        | Что делает                                             |
| ------------ | ------------------------------- | ------------------------------------------------------ |
| `load_const` | `value` — константа, `reg`      | записывает константу `value` в регистр `reg`           |
| `read`       | `reg` — регистр, `addr` — адрес | записывает значение из памяти по адресу `addr` в `reg` |
| `write`      | `ptr`, `src` — регистры         | записывает регистр `src` в память по адресу из `ptr`   |
| `sqrt`       | `ptr`, `src` — регистры         | записывает `sqrt(src)` в память по адресу из `ptr`     |

Здесь `reg`, `ptr` и `src` — номера регистров, `addr` — адрес памяти, `ptr` — регистр, в котором лежит адрес.
Порядок операндов внутри записи не важен, все операнды обязательны, лишние операнды не допускаются.

Пример (`examples/spec_tests.yaml`) — программа, результат трансляции которой совпадает со всеми тестовыми
байтовыми последовательностями из спецификации УВМ:

```yaml
- load_const: {value: 575, reg: 71}
- read: {reg: 41, addr: 726}
- write: {ptr: 36, src: 85}
- sqrt: {ptr: 48, src: 8}
```

### Поля команд

Размер команды — 6 байт, биты нумеруются с нуля от младшего. Поле `A` — код операции, оно есть у всех команд.

| Команда      | A (биты 0–4) | B                  | C                  |
| ------------ | ------------ | ------------------ | ------------------ |
| `load_const` | 7            | `value`, биты 5–36 | `reg`, биты 37–43  |
| `read`       | 13           | `reg`, биты 5–11   | `addr`, биты 12–31 |
| `write`      | 22           | `ptr`, биты 5–11   | `src`, биты 12–18  |
| `sqrt`       | 23           | `ptr`, биты 5–11   | `src`, биты 12–18  |

Допустимые значения: `value` — от 0 до 4294967295 (32 бита), `addr` — от 0 до 1048575 (20 бит), `reg`, `ptr`
и `src` — от 0 до 127 (7 бит).

### Машинный код

Поля `A`, `B` и `C` собираются в одно 48-битное число (каждое поле сдвигается на номер своего первого бита),
которое записывается в 6 байт от младшего байта к старшему. Команды в файле идут подряд без разделителей и заголовков,
поэтому размер файла равен числу команд, умноженному на 6.

Пример: `load_const` с `value=575`, `reg=71` — это `A=7`, `B=575`, `C=71`. Число `7 + (575 << 5) + (71 << 37)`
записывается как `0xE7, 0x47, 0x00, 0x00, 0xE0, 0x08`.

### Аргументы командной строки

```
main.py [-h] [-t] source output
```

| Аргумент       | Назначение                                                                      |
| -------------- | ------------------------------------------------------------------------------- |
| `source`       | путь к исходному файлу с текстом программы (YAML)                               |
| `output`       | путь к двоичному файлу-результату                                               |
| `-t`, `--test` | режим тестирования: вывести машинный код в байтовом формате, по команде в строке |
| `-h`, `--help` | вывести справку                                                                 |

Всегда выводится размер двоичного файла: `Размер двоичного файла: 24 байт`.

### Коды завершения

| Код | Значение                                                          |
| --- | ----------------------------------------------------------------- |
| 0   | программа ассемблирована, двоичный файл записан                   |
| 1   | ошибка в программе или файле (сообщение выводится в поток ошибок) |
| 2   | неверные аргументы командной строки                               |

Ошибки выводятся в виде `ошибка: команда N (имя): описание`, где `N` — номер команды в программе (с единицы).
Проверяются: наличие и формат файла, YAML, список команд, имя команды, набор операндов, тип и диапазон значений,
возможность записи результата. При ошибке двоичный файл не создаётся.

### Интерпретатор

```
interpreter.py [-h] -r FIRST LAST binary dump
```

| Аргумент                   | Назначение                                                                      |
| -------------------------- | ------------------------------------------------------------------------------- |
| `binary`                   | путь к двоичному файлу с ассемблированной программой                            |
| `dump`                     | путь к XML-файлу, в который сохраняется дамп памяти после выполнения            |
| `-r FIRST LAST`, `--range` | диапазон адресов памяти данных для дампа, границы включаются (число или `0x..`) |
| `-h`, `--help`             | вывести справку                                                                 |

Работа интерпретатора: файл читается и разбирается на команды по 6 байт, каждая команда переводится во внутреннее
представление, затем команды выполняются по порядку. Код завершения: 0 — успех, 1 — ошибка (файл, формат программы,
диапазон адресов, адрес вне памяти, `sqrt`), 2 — неверные аргументы командной строки.

Модель памяти:

- память команд — список команд, загруженных из файла; программа не может читать или менять её;
- память данных — 1048576 ячеек (адреса от 0 до 1048575, 20 бит), сначала все ячейки равны нулю;
- регистры — 128 регистров (номера от 0 до 127), сначала все равны нулю.

Выполнение команд (поля `B` и `C` — как в таблице «Поля команд»):

| Команда      | Действие                                                         |
| ------------ | ---------------------------------------------------------------- |
| `load_const` | регистр `C` = константа `B`                                      |
| `read`       | регистр `B` = память данных по адресу `C`                        |
| `write`      | память данных по адресу из регистра `B` = регистр `C`            |
| `sqrt`       | пока не реализована, интерпретатор завершается с ошибкой (этап 4) |

Если `write` берёт из регистра адрес за пределами памяти данных, программа завершается с ошибкой.

### Формат дампа памяти

Дамп — XML-файл в кодировке UTF-8. Корневой элемент `memory` хранит границы диапазона в атрибутах `first` и `last`,
каждая ячейка — элемент `cell` с атрибутом `address` и значением ячейки:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<memory first="10" last="12">
  <cell address="10">11</cell>
  <cell address="11">22</cell>
  <cell address="12">33</cell>
</memory>
```

### Модуль `uvm.vm`

| Объект                    | Назначение                                                        |

| `Machine.step()`          | выполнить одну команду                                            |

| Функция                         | Назначение                                          |

| `check_range(first, last)`      | проверить диапазон адресов дампа                    |

| `write_dump(path, text)`        | записать дамп в файл                                |

### Модули `uvm.cli` и `uvm.interpreter_cli`

| Функция                          | Назначение                                                      |
| -------------------------------- | --------------------------------------------------------------- |
| `build_parser()`                 | создать разборщик аргументов командной строки                   |
| `print_machine_code(items, out)` | вывести машинный код в байтовом формате                         |
| `run(args, stdout)`              | ассемблировать, записать файл, вывести результат                |
| `main(argv, stdout, stderr)`     | запустить ассемблер и вернуть код завершения                    |
| `parse_address(text)`            | (`interpreter_cli`) разобрать адрес: число или `0x..`           |

В `interpreter_cli` функции `build_parser`, `run` и `main` устроены так же, но для интерпретатора.

## Сборка и запуск

Сборка не требуется. Нужен Python 3.8+ и библиотека PyYAML:

```
pip install -r requirements.txt
```

Запуск ассемблера:

```
sh run.sh examples/spec_tests.yaml result.bin --test     # Linux и macOS
run.bat examples\spec_tests.yaml result.bin --test       # Windows
```

Запуск интерпретатора (сначала ассемблируйте программу):

```
sh run_interpreter.sh result.bin dump.xml --range 10 24  # Linux и macOS
run_interpreter.bat result.bin dump.xml --range 10 24    # Windows
```

Запуск тестов (находятся в каталоге `tests`):

```
sh scripts/run_tests.sh                                  # Linux и macOS
scripts\run_tests.bat                                    # Windows
PYTHONPATH=src python3 -m unittest discover -s tests -v  # то же самое напрямую
```

Тесты из спецификации УВМ проверяют, что для каждой команды ассемблер получает те же поля и значения
(`tests/test_spec_commands.py`) и те же байты (`tests/test_machine_code.py`), что указаны в спецификации.
Тест `tests/test_copy_array.py` выполняет программу копирования массива. Остальные тесты проверяют сообщения
об ошибках, декодирование, модель памяти, XML-дамп и командную строку ассемблера и интерпретатора.

Демонстрация (три запуска: тесты спецификации, программа с комментариями, программа с ошибкой):

```
sh scripts/demo.sh        # Linux и macOS
scripts\demo.bat          # Windows
```

Демонстрация этапа 3: ассемблирование программы копирования массива, выполнение и вывод дампа:

```
sh scripts/demo_interpreter.sh    # Linux и macOS
scripts\demo_interpreter.bat      # Windows
```

Двоичные файлы в репозиторий не добавляются: `*.bin` указан в `.gitignore`.
